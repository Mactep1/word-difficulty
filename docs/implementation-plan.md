# 英文书籍与字幕词汇分级软件：开发计划

日期：2026-11-17

状态：首版已实现；格式解析、中文界面、词表与真实模型推理已验证，真实材料人工难度评估待做。
调研依据：[Hugging Face 模型与数据集调研](./huggingface-word-difficulty-research.md)。

## 1. 产品目标与默认设定

用户上传英文书籍或字幕，软件提取词汇，合并词形，排除已设定的初学者等级，生成按 CEFR 难度排列的词汇表，并保留原文例句和位置。

为使第一版可以直接开工，采用以下默认设定；这些是产品选择，可以调整：

- 本机运行，中文浏览器界面；文件解析和模型推理均在本机完成。
- 默认显示 B1、B2、C1、C2，支持调整最低显示等级，以及查看 A1、A2。
- 分级采用词表查询与上下文模型结合的方式；首次配置需下载数据和模型，配置完成后支持离线使用。
- 第一个可运行版本支持 TXT、EPUB、SRT、VTT；随后增加 DOCX、文本型 PDF、ASS/SSA。
- 默认导出 CSV 和 XLSX，同时保留 JSON 分析结果供复查。
- 暂不加入账号、云端存储、手机应用、自动中文释义、Anki 同步和扫描 PDF 的 OCR。

“全部非初学者单词”在实现上的要求是：完整扫描解析到的正文，不限制输出数量；不能确定等级的候选词进入“待确认”，不能因为查不到词表就丢弃。识别与分级会有误差，因此需要展示解析状态、未评级词和判定来源。

## 2. 用户操作流程

1. 上传文件，展示提取文本预览、文件信息和解析提示。
2. 选择最低等级，以及是否显示专有名词、待确认词。
3. 开始分析，展示解析、语言处理、查表、模型判定四个阶段的进度。
4. 查看 B1–C2 分组、待确认列表、频次和原句；可按等级、词频、字母顺序排序与搜索。
5. 导出当前筛选结果，或导出包含全部等级和未评级词的完整结果。

## 3. 数据与分级规则

### 3.1 文本与词汇提取

- 各解析器统一输出正文片段及来源位置：章节、段落、页码或字幕时间；位置缺失时明确留空。
- EPUB 按正文阅读顺序解析；字幕移除时间轴、格式标签，并处理跨字幕断句和连续重复字幕。
- 保留原始片段，同时生成用于分句与分析的清洗文本，例句与位置需要能追溯到原文件。
- 使用英文分词、词形还原和词性标注，保留原始形式，例如 investigated / investigating → investigate。
- 标点、纯数字、网址等不进入词表；专有名词单独记录，默认隐藏，允许查看。
- 对缩写、所有格、连字符、混合语言字幕建立明确处理规则；无法可靠处理的内容保留诊断信息。
- 单词分级为第一版重点；短语动词、习语和其他多词表达列入后续迭代，不宣称第一版已经覆盖。

### 3.2 CEFR 判定

1. 以 lemma + 词性查询 `w3nabil/english-cefr-wordlist`，保留数据来源与版本。
2. 对词表未覆盖、词性无法匹配、存在可识别歧义的条目，调用 `star092304/cefr-level-deberta-v3-base`。
3. 模型输入使用“原句 + 目标词”，按训练方式组织；长句先截取包含目标词的上下文窗口，避免目标词被截断。
4. 同一词出现于不同词性或上下文时，可产生不同等级。结果按 lemma + 词性 + 等级聚合，提供多个代表例句，不把所有词义强行合成最高等级。
5. 保存预测等级和模型概率。低置信度、来源冲突及模型失败的条目进入“待确认”；概率只是模型输出，不当作准确率展示。
6. 使用批量推理及缓存；缓存键包含文本上下文、目标词位置、模型版本和处理规则版本，避免跨词义或更新后误用结果。

词表没有完整词义信息，直接查表仍可能误判简单词的生僻义。质量评估需专门检查这类样本，再决定是否扩大上下文推理范围。

### 3.3 输出字段

| 字段 | 内容 |
| --- | --- |
| 单词 | 词形还原后的 lemma |
| 原始形式 | 文中出现的不同拼写与屈折形式 |
| 词性 | 名词、动词、形容词等 |
| CEFR / 状态 | A1–C2，或待确认 |
| 频次 | 该聚合条目的出现次数 |
| 例句 | 来自原文的代表句子 |
| 来源位置 | 章节、段落、页码或字幕时间 |
| 判定来源 | 词表、模型或冲突待确认 |
| 模型概率 | 仅模型判定时填写；查表结果不伪造概率 |

分析摘要另外包含解析字数、候选词数、已分级数量、待确认数量、隐藏的专有名词数量，以及各等级统计。被隐藏和被阈值过滤的数据仍可从完整结果中查看。

## 4. 技术方案与模块

建议使用 Python 核心库 + Streamlit 本地界面。先完成可测试的核心处理，再接界面，方便以后增加桌面外壳或命令行批处理。

| 模块 | 职责 | 初步选择 |
| --- | --- | --- |
| 文件解析 | 多格式文件 → 带位置的正文片段 | TXT 标准库；EPUB、字幕、DOCX、PDF 使用各自解析库，实施时核实维护状态与接口 |
| 语言处理 | 分句、词性、lemma、词语位置 | spaCy 英文模型 |
| 词表查询 | lemma + 词性 → 等级及来源 | 本地 CEFR 词表索引 |
| 模型推理 | 上下文 + 目标词 → 等级概率 | Transformers + PyTorch；CPU 可运行，存在兼容 GPU 时可选加速 |
| 分析调度 | 批量处理、进度、聚合、错误报告 | 独立 Python 服务接口 |
| 缓存 | 已分析上下文的推理结果 | SQLite |
| 导出 | 分级词表、分析摘要 | CSV、JSON、openpyxl 写 XLSX |
| 界面 | 上传、配置、进度、筛选、下载 | Streamlit 中文界面 |

项目目录建议：

```text
src/word_difficulty/
  parsers/          # 各格式解析与统一来源位置
  nlp.py           # 分词、词性、lemma、上下文
  lexicon.py       # CEFR 词表适配
  classifier.py    # 模型加载、窗口化与批量推理
  pipeline.py      # 分析调度与聚合
  cache.py         # 版本化推理缓存
  export.py        # CSV / JSON / XLSX
  models.py        # 正文片段、词语出现、分级结果
  app.py           # 中文界面
tests/
  fixtures/        # 自建小型书籍与字幕样例
docs/
```

实施时创建项目虚拟环境，固定实际验证过的依赖、模型和数据版本。模型权重及用户上传文件不提交到源码目录。

## 5. 分阶段实施与验收

### 阶段 1：打通核心流程

交付：项目骨架、统一数据结构、TXT / SRT / VTT 解析、词形还原、词表查询、CSV / JSON 导出及可重复执行的命令行入口。

验收：

- 自建文本和字幕样例可生成按 CEFR 排序的词表。
- 屈折形式合并正确；不同词性可分开；词频和原文位置可核对。
- 默认排除 A1/A2，未知词保留在待确认列表；结果不做数量截断。
- 字幕时间轴、标签、重复字幕不会被统计为单词或重复增加频次。

此阶段只用于验证流程，词表未覆盖的词尚无模型等级，不能作为完整产品交付。

### 阶段 2：接入上下文模型与 EPUB

交付：模型和词表配置入口、EPUB 阅读顺序解析、上下文推理、批量处理、缓存、待确认规则及质量统计。

验收：

- 使用真实 checkpoint 完成端到端推理，确认 A1–C2 标签映射及双输入格式。
- 代表例句中的目标词在模型输入窗口内；同词不同上下文的缓存不会串用。
- 使用有区别的上下文验证多义词处理；验证长句、空文本、文件损坏、模型未安装及推理失败时的行为。
- 重复分析命中缓存；更新模型或规则后不会继续使用旧结果。
- 首次配置完成后，在不联网的环境中可分析测试文件。

### 阶段 3：完成可用的中文界面

交付：上传与预览、最低等级设置、分析进度、分组词表、搜索排序、待确认视图、CSV / XLSX 下载、Windows 启动说明。

验收：

- 用户按说明启动后，可以从上传一直完成到导出。
- 界面统计、筛选结果和导出行数一致；例句、字幕时间和章节信息可追溯。
- 模型首次配置、解析失败和空结果都有可操作提示。
- XLSX 按等级分工作表，另有待确认与摘要表；CSV 使用兼容中文 Excel 的编码。

完成本阶段即形成首个可交付 MVP：TXT、EPUB、SRT、VTT → 分级词表。

### 阶段 4：扩展格式与验证真实材料

交付：DOCX、文本型 PDF、ASS/SSA 支持，代表性真实材料评估，性能记录，安装与使用文档。

验收：

- 各格式都有小型样例验证正文提取与来源定位；PDF 多栏、页眉页脚等提取问题在预览中可检查。
- 扫描 PDF 检测不到正文时明确提示需要 OCR，不返回假成功。
- 选取合法可用的小说、非虚构文本、对话字幕各至少一份，记录词数、耗时、缓存命中、待确认比例和运行设备。
- 建立人工核对样本，覆盖 B1+ 与 A1/A2 边界、屈折词、多词性、生僻义、人名、俚语和字幕碎片。
- 比较查表、模型、混合方案，报告 B1+ 精确率/召回率和 CEFR 混淆情况；泛化评估按 lemma 隔离，避免同词跨训练与评估造成误导。
- 数据再分发前核实上游词表署名与使用条件，将数据、模型来源和实际采用版本写入说明。

质量指标在建立标注样本后确定首版基线；现有模型报告的分数不作为本软件的验收分数。没有人工核对结果时，明确标记评估未完成。

## 6. 实施顺序与完成定义

依赖顺序：阶段 1 → 阶段 2 → 阶段 3 → 阶段 4。每阶段先交付可运行结果，再增加下一层能力。

本计划实施完成时，交付内容应包括：可在 Windows 本机启动的中文应用、七类格式族（TXT / EPUB / SRT / VTT / DOCX / PDF / ASS/SSA）的解析、完整词汇扫描、可调初学者阈值、CEFR 分组与待确认列表、三种导出格式、经过验证的依赖配置、模型/词表配置说明、测试样例和已知限制。

实施记录与验证结果见 [开发状态](./development-status.md)。本文件保留原始分阶段验收范围。
